- **Status:** Accepted, In progress (implemented; PR open)

- **Depends on:** R-0018 (`Mesh`, its face rule, the depth order),

- **Realized by:** [SPEC-0020](../specs/0020-load-models.md)
- **QA:** `qa` agent run scoped to this requirement

## 1. Statement

motoreel must load low-poly meshes from **Wavefront OBJ** text, so props
and equipment are modelled in a modelling tool (Blender) and rendered by
motoreel. Loading is deterministic: the same text gives the same meshes,
the same meshes give the same frames.

Concretely:

1. **Geometry.** Vertices (`v`), faces (`f`, any index form, relative
   indices included) and objects (`o`) are read. Every `o` becomes its
   own `Mesh`, so the R-0018 depth sort orders parts as wholes.
2. **Faces.** A face the `Mesh` rule accepts (planar, strictly convex) is
   kept whole. Any other face is triangulated deterministically.
3. **Materials.** `usemtl` names select material slots. The caller binds
   each name to a `Material`; a name's first word `skin` or `inner` sets
   the `Layer` the finishes read, so a model marks its own inside.
4. **Axes and units.** Metres. A fixed, documented transform carries
   Blender's frame (+z up, −y front) into motoreel's (+y up).

## 2. Rationale

The owner installed Blender 5.3.0 (2026-11-22). Hand-coding equipment as
Rust generators (rotorf-sico's rack, pulley machine and bench) has been
slow, expensive in tokens and crude, and a hand-placed pulley column hid
the lifter in rotorf-sico's lateral-3d reel. The owner's decision: Blender
**models**, motoreel **renders**, so frames stay byte-deterministic and
independent of the modelling tool's version. The next fbf reels do the
x-ray during a 3D orbit among real-looking equipment.

**Why OBJ.** It is plain text, the subset needed is five statements, and
the parser needs no dependency (AC8). glTF carries scenes, animation and
binary buffers motoreel does not need and would need a JSON parser; it
can be a later requirement.

## 3. Acceptance criteria

- **AC1. The statements.** `v` (3 coordinates, or 6 with a colour that is
  ignored), `f` (`v`, `v/vt`, `v//vn`, `v/vt/vn`; negative indices count
  back), `o`, `usemtl` and `#` comments are read. `vn`, `vt`, `vp`, `s`,
  `g` and `mtllib` are skipped. Numbers parse with `str::parse::<f64>`
  (correctly rounded). Each `o` with faces is one mesh holding only the
  vertices and materials it uses, in file and `usemtl` order, so **a mesh
  written as OBJ reads back equal** (`PartialEq`, exact `f64`).
- **AC2. Faces.** A planar, strictly convex face stays one face. Any other
  face drops repeated and collinear corners and is ear-clipped, always
  taking the first ear in its own vertex order; the triangles keep the
  face's winding and tile it. Same text, same triangles.
- **AC3. Axes.** `Axes::ZUp` maps `(x, y, z)` to `(x, z, 0 − y)`, a proper
  rotation, so windings survive and Blender's front faces motoreel's
  default camera; `Axes::YUp` is the identity. Units are metres both ways.
- **AC4. Materials.** Faces before any `usemtl` are made of the empty
  name. Every used name must be bound by the caller, or loading fails with
  `Unbound(name)` at its first face. A first word (split at `_` or `.`) of
  `inner` or `skin` sets `Layer::Inner` or `Layer::Skin` on the bound
  material; other names keep the bound material's layer.
- **AC5. Errors, never panics.** Bad input is a typed `ObjError` carrying
  the 1-based line: unsupported statement, vertex arity, a bad number, a
  non-finite coordinate, an index of 0 or not yet defined, a face with
  fewer than three corners, a face with no area, a self-crossing face, a
  missing name, an unbound material. Arbitrary text never panics.
- **AC6. A loaded mesh renders like the hand-built one.** A skin cube over
  an inner octahedron, written as Blender would write it, loads to meshes
  equal to the same meshes built by hand in motoreel's frame, and renders
  byte-identical PPM frames under `Faceted`, `XRay` and a `Sweep`.
- **AC7. Determinism.** Two parses of each committed prop are equal; two
  renders of a loaded prop are byte-identical.
- **AC8. The kernel stays thin.** Zero new dependencies; the loader is in
  the core, so `--no-default-features` builds and tests it.
- **AC9. The committed props.** `assets/props/` holds a power rack, a
  cable machine, a flat bench, a dumbbell, a barbell with plates, an
  incline curl bench and a preacher curl bench, each
  generated by `tools/blender/props.py` (fixed parameters, no randomness)
  and committed with it. Each loads with the documented material names,
  each ink hull precedes its part, and the cable machine marks its shroud
  `skin` and its weight stack `inner`. Each is at most 1 500 triangles,
  hulls included.

## 4. Constraints & non-goals

- **Not glTF, FBX or binary formats**, and not `.mtl`: colours belong to
  the reel's palette, bound by name in code, not to the modelling tool.
- **Not scaling.** Motors cannot scale; a model in other units is
  exported in metres.
- **Not normals, UVs, smoothing groups, lines, curves or free-form
  surfaces.** Faces are flat (R-0018 §4).
- **Not a scene format.** Objects carry no pose; the reel poses each with
  a motor track.
- **Blender is not run by the engine or CI.** The script is a tool; the
  OBJ files are the committed inputs.

## 5. Open questions

None. The axis convention and the layer tags are fixed in AC3 and AC4.

## 6. Decision log

| Date | Decision | Rationale |
|------|----------|-----------|
| 2026-11-22 | **Accepted** and **In progress** on the owner's brief: Blender models, motoreel renders; OBJ first, glTF later | The owner's brief, 2026-11-22 |
| 2026-11-22 | **Valid faces stay whole; only the rest are triangulated** | The brief says to triangulate n-gons. Splitting every quad would double the faces, add seams the 2 px self-stroke must close, and make a loaded cube differ from `Mesh::cube`. Keeping valid faces gives AC1's round trip and AC6's equivalence; ear clipping covers concave and bent faces. Recorded for the owner's review |
| 2026-11-22 | **One mesh per `o`** | R-0018 orders objects as wholes inside a depth group; a prop as one mesh would fall back to the face-level sort that left zigzags in the spike |
| 2026-11-22 | **Layer tags in the name, not in a `.mtl`** | Blender writes material names into the OBJ; a name survives every exporter, a custom `.mtl` field does not |
| 2026-11-22 | **Ink hulls are modelled, not computed** | Growing a general mesh along vertex normals is not exact for every part; the script grows each convex primitive by `INK` and reverses it, the same rule as the curl example's kit |
| 2026-11-22 | **`tools/blender/` and `assets/props/` live in motoreel** | The convention (axes, names, hulls) is the loader's, and the tests load the committed files; one repo tests both ends. The kit layer (guion-video-creator) was the alternative and can vendor the files later |
| 2026-11-22 | **Two curl benches join the props: `incline_bench` and `preacher_bench`** | The owner asked for them for the 3D incline-or-preacher curl reel (rotorf-sico, fbf) and authorised the change once CI is green. Same pipeline and rules as AC9: fixed parameters in `props.py`, the house names, hulls first, under 1 500 triangles. Their slanted pads are boxes turned about x (`slab`), so every quad stays planar after six decimals |

## Prior art

- Wavefront Technologies, *The Advanced Visualizer*, appendix B1, "Object
  Files (.obj)".
- D. Eberly, "Triangulation by Ear Clipping", Geometric Tools, 2002.
- M. E. Newell's normal of a polygon, as in F. S. Hill, *Computer Graphics*,
  1990.
- Blender's OBJ exporter (`bpy.ops.wm.obj_export`), `forward_axis='Y'`,
  `up_axis='Z'`: its native frame, untouched.
